# Project Sirens / Sales Bot

An automated proactive conversational sales agent designed to run on
embedded hardware like a Raspberry Pi 5: it watches a camera feed,
detects people, and speaks personalized audio sales pitches at them
without waiting to be approached. The pitch content is generated by an
LLM from visual attributes and live inventory data.

**Version:** 1.5.1

## Architecture

An asynchronous, decoupled edge-cloud split across microservices
managed by Docker (Compose/Swarm):

- **IPC bus (Redis)** — pub/sub messaging between services, keyed by
  `NODE_ID`.
- **Vision engine** (`src/vision.py`) — YOLOv11 person tracking with
  distance calibration; facial embeddings to identify repeat customers.
- **Conversational agent** (`src/llm_client.py`) — streaming OpenAI
  `gpt-4o-mini` integration; turns visual attributes into "cold open"
  pattern-interrupt pitches; stateful multi-turn dialogue with dynamic
  A/B strategy assignment (persona derivation + contextual bandit
  weighting, v1.5.1).
- **Audio pipeline** (`src/audio_input.py`, `src/audio_output.py`) —
  speech-to-text for customer replies; streaming LLM output chunked
  into sentences for the Piper TTS engine via `aplay`.
- **Analytics hub** (`src/analytics.py`, `src/dashboard.py`) — central
  node aggregating kiosk metrics into SQLite and serving a FastAPI
  dashboard (Chart.js) with conversion funnel and A/B strategy views.
- **Point-of-sale** (`src/pos_client.py`) — injects dynamic pricing
  (scarcity premiums, fire-sale discounts) from live inventory into
  the prompt.

Behavior is driven by local JSON in `config/` (`inventory.json`,
`prompt_modifiers.json` — sales framework, tactics, constraints).

## Run

```bash
git clone --recursive https://github.com/robertpelloni/sales_bot.git
cd sales_bot
export OPENAI_API_KEY=<redacted>
docker-compose up --build -d   # Redis + hub + two mock edge kiosks; maps /dev/video0
```

Bare metal: install Redis and system deps, `pip install -r
requirements.txt`, then `python3 -m src.main --mode all`. A benchmark
mode (`src/demo_benchmark.py`) mocks a camera detection and measures
time-to-first-audio through the pipeline.

## Status

Prototype under active development through November 2026 (last commit
2026-11-07). The code is real (~50 KB Python in `src/`, plus tests and
Docker configs). What is **not** established by anything in this repo:
any deployment in a real store, any measured sales outcome, or the
"sub-second latency" claim — those are design goals, not verified
results. Note the vision engine identifies repeat customers by facial
embedding; anyone deploying this should consider the consent and
privacy implications for the venue.
